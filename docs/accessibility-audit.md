## 需另行規劃的問題（未重構）

1. **多視窗的焦點與層級（2.1.1、2.4.3、4.1.2）**：`Window.vue` 開啟時只提升 z-index，未將 DOM 焦點移入，關閉後也未還原至觸發按鈕；鍵盤切至後方視窗時不會自動提升該視窗。視窗尚缺與標題的程式化關聯。需統一設計非模態視窗語意、焦點進出及鍵盤切換行為，不能只加 aria-modal 或一律限制焦點。
2. **拖曳／縮放（2.1.1）**：`useWindowControls.ts` 的移動與邊緣縮放只處理 pointer 事件。需評估哪些功能是閱讀內容所必需，再提供鍵盤替代。另發現 `toggleMaximized()` 目前僅呼叫 `focusWindow()`，最大化／還原按鈕尚未實際切換狀態；本次保留其行為，需另案確認修復。
3. **載入、歡迎影片與小螢幕警告（2.4.3、4.1.2）**：全畫面遮罩沒有一致的焦點管理，背景導覽仍可能取得焦點。需設計遮罩期間的 inert／焦點隔離、關閉後焦點還原及可辨識名稱；動畫期間也需評估對比與 prefers-reduced-motion。未直接變更載入流程。
4. **遊戲（1.1.1、2.1.1、2.1.2）**：外層 iframe 有標題，但 Unity canvas 缺少可讀替代內容，且目前 tabindex="-1"；操作說明有滑鼠射擊，需確認鍵盤替代與離開遊戲焦點的方式。需連同 Unity 原始專案、遊戲玩法及替代體驗評估，未修改編譯後的遊戲檔案。
5. **終端機與文件結構（1.3.1、2.4.2）**：關於頁以大量終端機輸出及 ASCII 圖呈現；需人工測試螢幕閱讀器的朗讀負擔並規劃一般文字閱讀入口。友情連結與關於頁目前也缺少頁面 h1。頁面標題外掛會逐字清空／重寫標題，實測曾出現重複字串；建議另行整理標題更新流程。
6. **搜尋結果通知（4.1.3）**：友情連結篩選會更新內容，但未提供獨立 live status 通知結果數。建議另補簡短結果狀態，避免把整個連結列表設成 live region。
